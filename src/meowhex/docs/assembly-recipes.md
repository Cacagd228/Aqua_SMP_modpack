# Последовательная сборка

## Включение и отключение

Вся механика выключается одним флагом в
`config/meowhex-assembly.toml` → `assembly.enabled` (по умолчанию `true`).
Перезапуск игры — и обратно, пересборка не нужна.

При `enabled = false`:

- все пять рун (четыре активатора + вливание эфира) дают мишап
  «последовательная сборка отключена на сервере»;
- страница сборки не появляется в JEI;
- пять соответствующих свитков (`scroll_loki_merge_entities`,
  `scroll_loki_absorb_gifts`, `scroll_loki_purify_essence`,
  `scroll_loki_draw_sacrifice`, `scroll_loki_infuse_aether`) выпадают из
  сундуков реже — они убраны из пула.

Чего флаг **не** делает намеренно:

- **Руны остаются зарегистрированными.** `LookupPatternComponent` ищет
  `op_id` страницы через `getHolderOrThrow`, поэтому незарегистрированная
  руна — это не пустая страница, а краш при её открытии. Пять страниц
  Patchouli, пять ачивок и пять предметов-свитков ссылаются на эти id.
- **Сериализатор рецептов остаётся.** Иначе JSON вида `meowhex:assembly`
  начнёт сыпать ошибками на каждом `/reload`.

Иными словами, при `false` фича недоступна для игрока, но данные остаются
целыми и валидными — включение обратно ничего не ломает.

## Тестовые рецепты

Не настоящие рецепты — только чтобы проверить руны. Смело удаляй эту папку,
когда механика заработает.

Формат (`type: "meowhex:assembly"`):

| Поле | Что |
|---|---|
| `input` | заготовка, обычный ингредиент |
| `steps` | полный порядок шагов, массив строк. Один шаг — `["merge"]` |
| `mana` | сколько эфира нужно к концу сборки, в манах. Необязательно |
| `output` | результат. В 1.21 поле называется `id`, а не `item` |

Лишние поля в JSON не допускаются: `_comment` в файле рецепта ломает загрузку.

## Что здесь лежит

| Файл | Шаги | Заготовка | Результат |
|---|---|---|---|
| `test_merge.json` | `merge` | железный слиток | золотое яблоко |
| `test_absorb.json` | `absorb` | железный слиток | золотая морковь |
| `test_purify.json` | `purify` | медный слиток | изумруд |
| `test_sacrifice.json` | `sacrifice` | золотой слиток | незеритовый лом |
| `test_two_step.json` | `merge` → `purify` | блок железа | блок алмаза |
| `test_all_steps.json` | все четыре + 2000 эфира | осколок аметиста | блок незерита |
| `test_mana_only.json` | `absorb` → `sacrifice` + 5000 эфира | лазурит | аметистовый кластер |

## Порядок проверки

1. **Один шаг.** Два депо: в A — заготовка из строки, в B — любой расходник
   (его вид не важен, руна ест его количество и всё). Кастнуть нужную руну →
   в A сразу появился результат, в B стало на 1 меньше.
2. **Два шага.** `test_two_step`: сначала `merge`, потом `purify`. На втором шаге
   должен получиться блок алмаза. Если кастнуть `purify` первым — mishap
   «шаг ведёт в никуда», заготовка и расходник не тронуты.
3. **Эфир.** `test_mana_only`: сначала оба шага, потом руна эфира с числом 5000
   или больше. Результат появится на руне эфира. Если влить 1000 — сборка не
   завершится, эфир просто накопится на заготовке.
4. **Всё сразу.** `test_all_steps`: четыре шага по порядку и 2000 эфира в любой
   момент. Проверь, что в неверном порядке (`purify` первым) — mishap.
5. **Стек.** Положи в A сразу 8 заготовок, в B — 3 расходника → mishap
   «расходника не хватает». 8 и 8 → обработаются все восемь.

## Из чего писать свои

```json
{
  "type": "meowhex:assembly",
  "input": { "item": "minecraft:amethyst_shard" },
  "steps": ["merge", "purify"],
  "mana": 1000,
  "output": { "id": "meowhex:какой_нибудь_предмет" }
}
```

Шаги: `merge`, `absorb`, `purify`, `sacrifice`. Эфир шагом не пишется — сколько
его влить, игрок решает в момент каста, а `mana` в рецепте и есть проверка.
